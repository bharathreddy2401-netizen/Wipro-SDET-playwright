Promises
----------
avaScript Promises are objects representing the eventual completion (or failure) of an asynchronous operation and its resulting value.
Think of it like ordering food at a restaurant: you get a buzzer (the Promise) that stays quiet while the kitchen works, then eventually notifies you when your meal is ready or if they ran out of ingredients.

Synchronous and asynchronous
-----------------------------
In a synchronous model, tasks are performed one at a time. Each operation must finish before the next one begins. If one task takes a long time (like a heavy calculation), the entire program "freezes" and waits.

In an asynchronous model, the program can start a task and move on to the next one without waiting for the first one to finish. When the long-running task finally completes, the program is notified and handles the result.

The Three States of a Promise
-----------------------------
A Promise is always in one of these three states:

Pending: Initial state, neither fulfilled nor rejected. The "waiting" period.

Fulfilled (Resolved): The operation completed successfully. You have your data.

Rejected: The operation failed. You have an error message.

we create a Promise using the new Promise constructor, which takes a function (executor) with two arguments: resolve and reject.

const myPromise = new Promise((resolve, reject) => {
    const success = true;

    if (success) {
        resolve("Operation successful!");
    } else {
        reject("Something went wrong.");
    }
});

Once a promise is created, you need to handle the result. There are two primary ways to do this:

A. Using .then() and .catch()
This is the classic method for handling the asynchronous "pipeline."

.then() runs if the promise is fulfilled.

.catch() runs if the promise is rejected.

.finally() runs regardless of the outcome.

myPromise
    .then((data) => console.log(data))   // "Operation successful!"
    .catch((err) => console.error(err))  // "Something went wrong."
    .finally(() => console.log("Done"));

    Why Use Promises?
Before Promises, JavaScript relied on callbacks. If you had multiple asynchronous tasks, you ended up with "Callback Hell"—deeply nested code that was nearly impossible to debug.

Feature,                            Callbacks,                                       Promises
--------------------------------------------------------------------------------------------------------------------------
Readability,                       |"Poor (Nested ""Pyramid of Doom"")",            |High (Linear Chaining)
Error Handling,                    |Hard (Must handle in every function),           |Easy (Centralized .catch())
Control Flow,                      |Difficult to manage,                            |Built-in methods like Promise.all()

fetching APIS:
--------------
To fetch an API in JavaScript, you are essentially asking a remote server for data. Because the server might be across the world, this process is asynchronous—your code starts the request and then "waits" for the data to come back without stopping the rest of your program.

example:

fetch("https://fakestoreapi.com/products/1")
    .then(res => res.json())        // Convert response
    .then(data => console.log(data)) // Use data
    .catch(err => console.log(err)); // Handle errors

The Response Object (res):
----------------------------
A. The first thing fetch returns is not your data; it's a Response object.

It tells you if the request was successful (res.ok).

It tells you the status code (200 for success, 404 for not found).
B. JSON Conversion
Computers send data over the internet as a stream of "chunks." The .json() method is necessary because it tells JavaScript to wait for all the chunks to arrive and then turn them into an object you can actually use.
C. Error Handling
Always use .catch() or try/catch. Without it, if the API is down or the user loses Wi-Fi, your entire application might crash.

ASYNC and AWAIT:
----------------
async: A keyword used to declare a function. It ensures the function always returns a Promise. If you return a value, JS automatically wraps it in a resolved Promise.

await: A keyword that can only be used inside an async function. It pauses the execution of the function until the Promise is settled (resolved or rejected).


example:

    let data = await fetch("https://jsonplaceholder.typicode.com/todos"); // cursor is blocked in this line
    data = data.json();

OOP copcepts
-------------
abstraction:
Abstraction focuses on hiding the complex internal logic of an object and exposing only the essential features. 
It reduces complexity by allowing users to interact with a simple interface without needing to understand the underlying implementation.

Inheritence:
Inheritance allows a class (child/subclass) to acquire the properties and methods of another class (parent/superclass). 
This promotes code reusability and establishes a hierarchical relationship between different entities in the software.

Polymorphism:
Polymorphism ("many shapes") allows different classes to be treated as instances of the same parent class.

Method Overriding: A child class provides a specific implementation of a method that is already defined in its parent class.

Dynamic Binding: The ability of the program to decide which method to call at runtime.

Encapsulation:
Encapsulation is the bundling of data and the methods that operate on that data into a single unit (a class). It involves:

Data Hiding: Protecting the internal state of an object from unauthorized access.

Accessors: Using getters and setters to control how data is read or modified.

Private Fields: Using the # prefix in JS to ensure variables cannot be accessed outside the class scope.

Prototype:
-----------
Memory Efficiency: Instead of giving every instance of an object its own copy of a method (like .push() for arrays), the method lives on the Array.prototype. Every array you create simply "points" to that one method.

The "Undefined" Error: When you saw Cannot read properties of undefined (reading 'push'), it happened because the variable you were calling .push() on was undefined. Since it was undefined, it had no prototype to look up the .push method from.

Higher-Order Functions (HOFs):
--------------------------------
A function is "Higher-Order" if it does at least one of the following:

Takes one or more functions as arguments (callbacks).

Returns a function as its result.

Destructuring:
-----------------
Destructuring is a shorthand way to "unpack" values from arrays or properties from objects into distinct variables.
const user = { name: 'Alice', age: 25, city: 'London' };

// Unpacking properties
const { name, age } = user;

console.log(name); // 'Alice'

Array Destructuring
Variables are assigned based on their index (position):

const colors = ['red', 'green', 'blue'];

const [first, second] = colors;

console.log(first); // 'red'

SPREAD OPERATOR:
-----------------
The Spread operator "expands" an iterable (like an array or object) into its individual elements. Use it when you want to copy or merge data.
const parts = ['shoulders', 'knees'];
const body = ['head', ...parts, 'and toes']; 

// Result: ['head', 'shoulders', 'knees', 'and toes']

Rest Parameter (...):
---------------------
The Rest syntax looks exactly like spread but does the opposite. It "collects" multiple elements and condenses them into a single array. It is typically used in function arguments or destructuring.
function sum(...numbers) {
  // 'numbers' is now an array: [1, 2, 3]
  return numbers.reduce((acc, curr) => acc + curr);
}

sum(1, 2, 3);

GENERICS:
---------
Generics are like "blueprints for blueprints." They allow you to write code (functions, classes, or interfaces) that can work with any data type while still maintaining strict type safety.

Think of a Generic as a variable for a type. Instead of locking a function into just integers or strings, you use a placeholder.
Interface: Defines the "shape" (what properties exist).

Generics: Defines the "flexibility" (what data types those properties use).

A Tuple is essentially an array with a fixed number of elements where each element has a known type.

While a regular array is usually a collection of the same type (like a list of strings), a tuple allows you to store a specific sequence of different types.

partial:
----------
Makes all properties in an object optional.
omit:
---------
Omit<T, Keys>: Creates a new type by removing specific keys.

interface User {
  id: number;
  name: string;
  email: string;

type UpdateUser = Partial<User>; // { id?, name?, email? }

Readonly:
---------
Makes all properties immutable (ready-only). You cannot reassign them.
deep partial:
-----------------
This isn't built into TypeScript by default (TypeScript's Partial is shallow). A "Deep Partial" recursively makes every nested property optional.

Any type:
----------
Turns off type checking completely. It’s dangerous because it allows you to do anything (like calling a function that doesn't exist), leading to runtime crashes.

unknown type:
--------------
The safer sibling of any. It says "we don't know what this is yet." You must perform a type check (Type Guarding) before you can use it.

Type gaurding:
--------------
Type guarding is the process of narrowing down a type within a conditional block. It’s how you handle unknown or Union types (like string | number).

function process(input: string | number) {
  if (typeof input === "string") {
    // Inside this block, TypeScript knows 'input' is a string
    console.log(input.toUpperCase());
  } else {
    console.log(input.toFixed(2));
  }
}

typeof: Used in a type context, it extracts the type of a variable.

keyof: Takes an object type and yields a "union" of its keys.

Playwright is an end-to-end automation testing framework used for testing web applications. It supports multiple browsers like Chromium, Firefox, and WebKit using a single API. 
It is mainly used for UI testing, functional testing, and cross-browser testing. Playwright provides fast execution, auto-waiting, screenshots, video recording, tracing, and parallel execution features.
It supports JavaScript, TypeScript, Python, Java, and C#.

Two Principles in Testing: Expected and Actual : 

Expected Result : Expected result means the output that should happen according to requirements or business logic.
Actual Result : Actual result means the real output produced by the system during execution.

If both are same      → Test Pass
If both are different → Test Fail

Boundary Value Analysis (BVA) : Boundary Value Analysis is a black-box testing technique used to test values at the boundary limits because most errors occur at boundary values.
Example : If age field accepts values from 18 to 60

Test cases should be:

17 (just below minimum)
18 (minimum boundary)
19 (just above minimum)
59 (just below maximum)
60 (maximum boundary)
61 (just above maximum)
Parallelism : Parallelism means executing multiple test cases at the same time instead of one after another.
